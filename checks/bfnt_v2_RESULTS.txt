BFNT v2 coverage: verification record
=====================================
Recorded 2026-11-19 in the sandbox. This is sandbox evidence for a C test. It is not an environment gate (plan section 6.4).

Scope
- Changed: tests/ui/test_text.c only. src/engine/text/text.c is unchanged.
- Added: write_v2 (a BFNT v2 serializer that follows docs/text.md and text.c), make_v2_fixture (a hand-built font with
  known metrics and kerning), same_glyph and same_quad, and check_v2_format, which main calls after
  check_prebaked_roundtrip.
- Corrected: the check that set data[4] = 2 and was labeled "unsupported version". Version 2 is supported, so that
  file was rejected only because its header length was 48, not 52. It now sets data[4] = 5.

Why a writer and not a shipped file
- The upload has no v2 .bfnt file. Both shipped fonts are v4 (checked by reading bytes 4 and 6).
- tools/assets/font_bake.c writes only v4 (docs/text.md, "The builder writes BFNT v4").

Environment (sandbox)
- gcc 13.3.0 (Ubuntu 24.04). Flags: -std=c11 -g -O1 -Wall -Wextra -Werror -fsanitize=address,undefined
  -fno-sanitize-recover=undefined.
- stb_truetype.h: upstream v1.28, fetched from raw.githubusercontent.com/nothings/stb (master).
  SHA-256 428cfe93520f2aed5e413a220b0db5bba5b17e2ebe5a64e4a8efa9eeeb67ec5f, which matches the raw hash that
  docs/Bairava_Phase0/Bairava-Engine-Rendering-Migration-Plan.phase0-status.md records for commit 9600522.
  The commit itself was not checked against that hash.
- stb_truetype_impl.c: one line that defines STB_TRUETYPE_IMPLEMENTATION and includes the header. It is a shim,
  not the repository's file, because vendor/ is absent from the upload.
- FreeType 2.13.2 headers (libfreetype-dev 2.13.2+dfsg-1ubuntu0.2). vendor/freetype-2.15.0 is absent from the upload.
- Built in a scratch copy with vendor/ added. Nothing vendored was added to the deliverable tree.
