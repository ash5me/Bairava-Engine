What this file records
  checks/font_registry_mirror.c mirrors src/engine/text/font_registry.zig. It checks the control flow and the id
  rules under AddressSanitizer and UBSan. It does NOT compile the Zig. The sandbox has no Zig toolchain, so
  `zig build test` remains the first real check of font_registry.zig and of the D-03 change in shaper.zig.
  This is sandbox evidence. It does not close any environment gate in section 6.4 of the plan.

      checks/font_registry_mirror.c -o font_registry_mirror

Mirror-only checks (no Zig test yet)

  test_oom_spends_id      An insert whose table growth fails still spends its id, and the next insert gets a later
                          id. The Zig code documents this in Registry.insert. No Zig test injects the failure yet.
  test_random_model       200,000 random operations per run, against a reference model of live and removed handles,
                          with allocation failures injected on about 1 insert in 16. It runs twice.

Known gaps (recorded, not hidden)

  - Added after the mirror run: a Zig test covers the OOM rule. It is named "a failed insert stores nothing and
    spends its id, so a later insert never reissues it", and it uses std.testing.FailingAllocator with fail_index 0, as
    glyph_cache.zig and allocators.zig do. It mirrors test_oom_spends_id. Its second attempt accepts either outcome,
    because the allocator's behaviour after the failure index is not checked here. The mirror checks the success case.
    Not compiled in the sandbox; the owner's zig build test is the first check of it.
  - D-03 (ShapedRun.font_id, Shaper.initWithFontId) has Zig tests in shaper.zig and no C mirror. HarfBuzz is not
    modeled in the sandbox. Those tests run only under `zig build test`.
  - The mirror checks control flow. It is not evidence that the Zig compiles or that the Zig tests pass.
