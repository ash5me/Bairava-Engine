Bairava public API

This reference is generated from an explicit allowlist of canonical names exported by @import("bairava"). Only allowlisted entries are published; implementation target paths are validated but never displayed. The current public API is experimental and not production-ready.

bairava.Config

Kind: type
Stability: experimental
Summary: Application configuration, window, renderer, and runtime settings.

Contract: The parent allocator must outlive the entire run. Settings-file window values override the corresponding startup values. Config.validate returns a specific error before any platform resource is opened.

  • Config.allocator (allocators): Parent allocator for engine, game, asset, and frame allocations; it must remain valid through the full run. If worker_threads is nonzero, it must be thread-safe.
  • Config.window_w, window_h (fields): Initial native window dimensions in pixels; each must be from 64 through 8192.
  • Config.native_w, native_h (fields): Reference view dimensions in pixels. Both must be positive; at zoom 1, the limiting window axis matches this view and the other axis may show more world.
  • Config.clear_rgb (fields): Background RGB channels, each finite and in the inclusive range 0..1.
  • Config.update_hz (fields): Fixed simulation updates per second; must be greater than zero.
  • Config.zoom_min, zoom_max (fields): Finite positive zoom bounds that include 1: zoom_min must be at most 1 and zoom_max at least 1.
  • Config.zoom_rate (fields): Finite, non-negative zoom easing rate per second; zero snaps to the target.
  • Config.post_effects (fields): Ordered post-processing chain, limited by max_post_effects; an empty slice disables post-processing.
  • Config.texture_budget_bytes (fields): Approximate cache budget at four bytes per texel. Idle resources are evicted least-recently-used; zero means unlimited.
  • Config.texture_staging_budget_bytes (fields): Maximum staged texture payload bytes while waiting for upload. Zero removes the cap; a payload exceeding the whole budget fails.
  • Config.worker_threads (fields): Worker count from 0 through max_worker_threads. Zero runs background work on the main thread.
  • Config.validate (methods): Checks startup configuration before platform resources are created; it has no side effects.
  • Config.validationMessage (methods): Returns a stable human-readable explanation for a ValidationError; use the error value for programmatic handling.
  • Config.validate (returns): Returns void on success, otherwise one of ValidationError. The returned error can be rendered with validationMessage.
  • Config.ValidationError (errors): EmptyTitle and EmptySettingsFile identify empty required strings; InvalidWindowSize and InvalidNativeViewSize identify non-positive/out-of-range dimensions; InvalidClearColor, InvalidUpdateRate, TooManyWorkerThreads, InvalidZoomBounds, InvalidZoomRate, InvalidDebugFont, TooManyPostEffects, and InvalidPostParams identify the corresponding invalid field constraints.
  • Config.max_worker_threads (capacities): Hard upper bound of 32 background workers; validate returns TooManyWorkerThreads above it.
  • Config.post_effects (capacities): The post-effect chain is limited to max_post_effects; validate returns TooManyPostEffects when exceeded.

bairava.Context

Kind: type
Stability: experimental
Summary: Game-facing access to input, assets, rendering, audio, and other engine services.

Contract: Passed to init and update; its frame-scoped dt and input state are valid for that update. Resources loaded by the game must be released before shutdown. GPU work is performed on the engine thread.

  • Context.mouseWorld (methods): Maps the current input mouse position through the last presented view layout and current camera to world pixels; call during update.
  • Context.pollEvent (methods): Consumes the next translated event for this update, returning null when the queue is empty. Events are returned by value.
  • Context.loadTexture (methods): Loads and uploads immediately on the calling thread. The caller owns the returned Texture and must call deinit before run ends; file/decode errors are returned.
  • Context.acquireTexture, retainTexture, releaseTexture (handles): Named textures use counted handles: balance each successful acquire or retain with one release. releaseTexture clears the passed handle; resolution after unload/release reports a handle error.
  • Context.readFile (allocators): Reads a packaged file using the caller-supplied allocator; the caller owns the returned bytes and frees them with that allocator.
  • Context.uploadStaged (methods): Uploads staged pixels to the GPU on the engine thread. Staged CPU data may be freed as soon as the call returns.
  • Context.max_registered_textures (capacities): At most max_registered_textures distinct names may be registered; registerTexture returns an error when the limit is reached.

bairava.DrawContext

Kind: type
Stability: experimental
Summary: Frame-scoped rendering context supplied to game draw callbacks.

Contract: Valid only during draw. Submit drawing through its batch; do not retain the context or its frame-owned data.

  • DrawContext.batch (handles): Borrowed frame batch. Queue work only during draw; the engine owns GPU upload and submission.
  • DrawContext.cam (handles): Borrowed camera for this draw. World coordinates must be converted to view pixels before APIs that accept view-space coordinates.
  • DrawContext.view_w, view_h (fields): Current view dimensions in pixels; coordinate-space inputs to drawing are in this view.
  • DrawContext.alpha (fields): Interpolation factor from previous update (0) to latest update (1), intended for render-only interpolation.
  • DrawContext.dt (fields): Elapsed seconds since the previous presented frame, capped by the frame loop; use for frame-rate-independent presentation smoothing.

bairava.run

Kind: function
Stability: experimental
Summary: Runs a game through initialization, fixed-step updates, drawing, and shutdown.

Contract: The game type supplies init, update, and draw, plus optional teardown. init errors are returned and do not call game teardown; resources created before an init error must be released by init. A successful init is paired with teardown before platform resources are destroyed. update uses a fixed timestep; draw runs once per presented frame.

  • run.Game.init (callbacks): Called once on the engine thread after platform/runtime setup. An init error is returned by run and does not call game teardown; init must release any resources it acquired before failing.
  • run.Game.update (callbacks): Called zero or more times per rendered frame at the fixed update_hz rate. The Context and its input/dt are borrowed for that call.
  • run.Game.draw (callbacks): Called on the engine thread for each presented frame, after updates. DrawContext and frame-owned references must not escape the callback.
  • run.Game.deinit (callbacks): Optional teardown called exactly once after successful init, before platform and GPU resources are destroyed.
  • run.Config.allocator (allocators): The allocator supplied in Config must outlive the complete run call.

bairava.SpriteBatch

Kind: type
Stability: experimental
Summary: Frame-local sprite and lighting submissions for the renderer.

Contract: Use only from the draw callback. Submission order and z values control layering; the renderer owns upload and flush. The batch is not an independently initialized or drawable backend object.

  • SpriteBatch.begin (methods): Starts the frame and clears queued sprites, lights, shadows, and counters. The runtime calls it before game draw.
  • SpriteBatch.addLight (methods): Adds one view-space point light; returns false without modifying the batch when max_lights is reached.
  • SpriteBatch.addShadowSegment (methods): Adds one view-space occluder; returns false without modifying the batch when max_shadow_segments is reached.
  • SpriteBatch.addPointLightComponents, addShadowSegmentComponents (methods): Adds enabled values in input order and stops at capacity; the returned count is the number accepted.
  • SpriteBatch.deinit (methods): Releases backend and batch-owned GPU/CPU resources. The engine normally owns this lifecycle; game code should not deinitialize DrawContext.batch.
  • SpriteBatch.max_lights, max_shadow_segments (capacities): Fixed per-frame light and shadow capacities. Add methods report overflow through false or a partial accepted count.
  • SpriteBatch.gpu_state, flat_normal, white (handles): Backend and helper textures are batch-owned; do not retain or release their pointers independently.

bairava.Texture

Kind: type
Stability: experimental
Summary: GPU texture resource used by rendering operations.

Contract: A loaded texture is game-owned and must be deinitialized before the run ends. Asset loading can fail; GPU-backed operations remain on the engine thread.

  • Texture.width, height (fields): Texture dimensions in texels.
  • Texture.deinit (methods): Destroys GPU resources and invalidates the Texture value. Call exactly once while its owning engine runtime is alive.
  • Texture.isReady (methods): Reports whether an asynchronous upload has completed; textures without an upload fence are immediately ready.
  • Texture.isReady (returns): Returns true when the texture is safe to sample; it does not wait for an upload to finish.
  • Texture.gpu_state (handles): Opaque backend-owned state. It is not a game-facing handle and must not be copied for independent ownership.

bairava.LoadedAtlas

Kind: type
Stability: experimental
Summary: Loaded texture atlas and lookup information for its named regions.

  • LoadedAtlas.texture, index (fields): Owned GPU texture and CPU atlas index. The LoadedAtlas owner must deinitialize both together.
  • LoadedAtlas.region (methods): Returns a borrowed atlas region by name. A missing name is a programmer error and panics; validate names during content loading if they are not guaranteed.
  • LoadedAtlas.region (returns): The returned rectangle borrows the atlas index and is valid only while that index remains alive.
  • LoadedAtlas.deinit (methods): Releases the texture and atlas index; call once before the engine runtime ends.

bairava.TextureHandle

Kind: type
Stability: experimental
Summary: Counted handle to a texture registered with the engine context.

Contract: Each successful acquire/retain must be balanced by release. A released handle is invalid; operations that resolve stale handles return HandleError.

  • TextureHandle.acquireTexture, retainTexture, releaseTexture (handles): Each successful acquire or retain adds one reference; pair every reference with releaseTexture. Releasing clears the passed handle. Lookup can fail with InvalidHandle or StaleHandle.
  • TextureHandle.textureOf, retainTexture, releaseTexture (errors): InvalidHandle means the handle was never issued or was released; StaleHandle means its texture was unloaded. Reacquire by registered name after either error.

bairava.SceneHost

Kind: type factory
Stability: experimental
Summary: Generic scene-host type specialized for a game root type.

Contract: Instantiate with the root scene type and pass the resulting type to bairava.run. Scene callbacks are driven by the host; transitions are applied after update at a safe point.

  • SceneHost.Root.init (callbacks): Constructs a scene from a borrowed Context. The host owns the returned scene value; an init error leaves the existing scene stack active.
  • SceneHost.Root.update (callbacks): Runs only for the active scene; receives a borrowed Context and SceneNavigator. Requests are deferred until the update safe point.
  • SceneHost.Root.draw (callbacks): Draws open scenes bottom-to-top; DrawContext is borrowed for the callback.
  • SceneHost.Root.deinit / Root.deinitWithContext (callbacks): Optional teardown runs once when a scene is popped, replaced, or the host shuts down. Use deinitWithContext when resource release needs Context.

bairava.SceneNavigator

Kind: type
Stability: experimental
Summary: Navigation handle for requesting scene transitions.

Contract: Borrowed for the active scene’s update callback. A request is recorded and applied after updates at the next safe point; a later request replaces an earlier pending request.

  • SceneNavigator.switchTo (methods): Requests replacement of the active scene while keeping scenes below it open. The new scene is initialized before the replaced scene is released.
  • SceneNavigator.push (methods): Requests a new scene above the active scene, suspending but continuing to draw the prior scene. Applying beyond max_depth fails and leaves the stack unchanged.
  • SceneNavigator.pop (methods): Requests closing the active scene so the one below resumes. Popping the root is rejected when the request is applied; use switchTo to replace it.
  • SceneNavigator.max_depth (capacities): The scene stack holds at most eight scenes; an over-capacity push is refused when pending transitions are applied.
  • SceneNavigator.SceneNavigator (handles): Borrowed during the active scene’s update callback; do not retain it after update returns.
