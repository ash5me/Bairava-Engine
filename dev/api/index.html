Bairava public API

This reference is generated from an explicit allowlist of canonical names exported by @import("bairava"). Only allowlisted entries are published; implementation target paths are validated but never displayed. The current public API is experimental and not production-ready.

87 allowlisted exports. All entries inherit the project’s experimental API status. Callable export types are emitted from compiler reflection; contract notes are authored and reviewed in the manifest.

bairava.Config

Kind: type
Stability: experimental
Summary: Application configuration, window, renderer, and runtime settings.

Contract: The parent allocator must outlive the entire run. Settings-file window values override the corresponding startup values. Config.validate returns a specific error before any platform resource is opened.

  • Config.allocator (allocators): Parent allocator for engine, game, asset, and frame allocations; it must remain valid through the full run. If worker_threads is nonzero, it must be thread-safe.
  • Config.window_w, window_h (fields): Initial native window dimensions in pixels; each must be from 64 through 8192.
  • Config.native_w, native_h (fields): Reference view dimensions in pixels. Both must be positive; at zoom 1, the limiting window axis matches this view and the other axis may show more world.
  • Config.clear_rgb (fields): Background RGB channels, each finite and in the inclusive range 0..1.
  • Config.update_hz (fields): Fixed simulation updates per second; must be greater than zero.
  • Config.zoom_min, zoom_max (fields): Finite positive zoom bounds that include 1: zoom_min must be at most 1 and zoom_max at least 1.
  • Config.zoom_rate (fields): Finite, non-negative zoom easing rate per second; zero snaps to the target.
  • Config.post_effects (fields): Ordered post-processing chain, limited by max_post_effects; an empty slice disables post-processing.
  • Config.title, settings_file (fields): Null-terminated window title and non-empty executable-relative settings path; settings-file window values override initial window size, fullscreen, and vsync.
  • Config.fullscreen, vsync (fields): Initial window presentation settings; values from an existing settings file take precedence.
  • Config.debug_font_path, debug_font_px (fields): Executable-relative prebaked BFNT asset and its baked pixel height for the development overlay; invalid or missing font disables the overlay.
  • Config.log_file, crash_file (fields): Optional executable-adjacent output paths; null keeps logging in the terminal or disables crash-report file output.
  • Config.post_params (fields): Effect strengths for vignette, scanlines, and grayscale, each finite and within 0..1; padding is reserved.
  • Config.texture_budget_bytes (fields): Approximate cache budget at four bytes per texel. Idle resources are evicted least-recently-used; zero means unlimited.
  • Config.texture_staging_budget_bytes (fields): Maximum staged texture payload bytes while waiting for upload. Zero removes the cap; a payload exceeding the whole budget fails.
  • Config.texture_loads_per_frame (fields): Maximum queued texture preloads started between frames; zero disables background preloading.
  • Config.gpu_timing (fields): Enables development-only GPU timing by waiting for each frame’s GPU work; this stalls the CPU and changes measured frame cost.
  • Config.worker_threads (fields): Worker count from 0 through max_worker_threads. Zero runs background work on the main thread.
  • Config.validate (methods): Checks startup configuration before platform resources are created; it has no side effects.
  • Config.validationMessage (methods): Returns a stable human-readable explanation for a ValidationError; use the error value for programmatic handling.
  • Config.validate (returns): Returns void on success, otherwise one of ValidationError. The returned error can be rendered with validationMessage.
  • Config.ValidationError (errors): EmptyTitle and EmptySettingsFile identify empty required strings; InvalidWindowSize and InvalidNativeViewSize identify non-positive/out-of-range dimensions; InvalidClearColor, InvalidUpdateRate, TooManyWorkerThreads, InvalidZoomBounds, InvalidZoomRate, InvalidDebugFont, TooManyPostEffects, and InvalidPostParams identify the corresponding invalid field constraints.
  • Config.max_worker_threads (capacities): Hard upper bound of 32 background workers; validate returns TooManyWorkerThreads above it.
  • Config.post_effects (capacities): The post-effect chain is limited to max_post_effects; validate returns TooManyPostEffects when exceeded.

bairava.Context

Kind: type
Stability: experimental
Summary: Game-facing access to input, assets, rendering, audio, and other engine services.

Contract: Passed to init and update; its frame-scoped dt and input state are valid for that update. Resources loaded by the game must be released before shutdown. GPU work is performed on the engine thread.

  • Context.input, dt, simulation_tick (fields): Borrowed current-update state: latched input, fixed-step duration in seconds, and the zero-based simulation update index.
  • Context.running (fields): Set false to request that the main loop stop after the current update.
  • Context.scale_mode, renderer, zoom_target, zoom_min, zoom_max (fields): Presentation settings. scale_mode and renderer may be changed directly; zoom target should be changed through zoomBy/resetZoom to honor configured bounds.
  • Context.layout, camera (fields): Current view layout and borrowed gameplay camera. layout maps the last presentation’s window points; camera is mutable game state in world pixels.
  • Context.audio, immediate_present_supported (fields): Borrowed audio service and the active surface’s immediate-present capability; missing playback-device initialization leaves audio silent.
  • Context.textures, fonts, reloads, event_reader, diagnostics (fields): Engine-owned service pointers. Use their Context methods instead of mutating stores or retaining pointers beyond the run/update lifetime.
  • Context.settings_text, settings_file (fields): Startup settings contents and executable-relative settings path; text is borrowed and may be empty when no file exists.
  • Context.gpu_state, worker_allocator, jobs, diagnostics_enabled (fields): Runtime implementation state. GPU access is engine-thread-only; worker_allocator must be thread-safe; development-only diagnostics may be disabled in release builds.
  • Context.allocators (fields): Run-owned game, asset, and frame allocator scopes; their lifetime rules are described by Allocators.
  • Context.mouseWorld (methods): Maps the current input mouse position through the last presented view layout and current camera to world pixels; call during update.
  • Context.rendererBackend, setRendererBackend, toggleRendererBackend (methods): Read or request the renderer for the next frame. The reserved SDL2D request resolves to SDL_GPU until that backend is enabled.
  • Context.capabilities (methods): Returns a snapshot of renderer, texture, presentation, and audio-playback capabilities for this run.
  • Context.pollEvent (methods): Consumes the next translated event for this update, returning null when the queue is empty. Events are returned by value.
  • Context.zoomBy, resetZoom (methods): Change the bounded zoom target; the camera approaches it during presentation frames.
  • Context.loadTexture (methods): Loads and uploads immediately on the calling thread. The caller owns the returned Texture and must call deinit before run ends; file/decode errors are returned.
  • Context.stageFormats (methods): Reports compressed texture formats usable by the active renderer, for choosing a staged asset variant.
  • Context.registerTexture, acquireTexture, requestTexture, textureOf, unloadUnusedTextures, textureStats (methods): Named texture registry operations: register unique names before first use, acquire counted handles, queue prioritized preloads, resolve live references, unload unreferenced textures, and read counters.
  • Context.loadSound, openStreamed (methods): Load a short decoded sound or open a streamed sound for long-form audio; loaded Sound is caller-owned and deinitialized, while StreamedSound manages per-voice readers.
  • Context.readFile, writeFile, fileExistsBeside, removeFile (methods): Access packaged or executable-adjacent files with safe relative paths. Packaged files are read-only; writes/removes target the beside-executable location.
  • Context.saveBindings (methods): Persists the supplied action map’s bindings to the configured settings file for its compile-time action enum.
  • Context.watchAsset, watchAssetGraph, takeChanged, takeAssetChanged (methods): Register files or asset graphs for development hot reload and consume change notifications; release builds may not watch assets.
  • Context.waitGpuIdle (methods): Waits for the GPU to finish submitted work; use only when synchronization is required, not as a normal frame operation.
  • Context.loadFont, loadMsdfFont, loadOutlineFont, loadBitmapFont, unloadFont (methods): Load a baked, MSDF, TrueType outline, or bitmap font into the run-owned store and release it by handle when no longer needed. Pixel size is fixed at load time.
  • Context.loadAtlas (methods): Loads an image and index, checks that their dimensions match, and returns a caller-owned LoadedAtlas.
  • Context.acquireTexture, retainTexture, releaseTexture (handles): Named textures use counted handles: balance each successful acquire or retain with one release. releaseTexture clears the passed handle; resolution after unload/release reports a handle error.
  • Context.readFile (allocators): Reads a packaged file using the caller-supplied allocator; the caller owns the returned bytes and frees them with that allocator.
  • Context.relative, name, path, priority, allocator, bytes (parameters): Asset paths are safe relative paths; names follow registry rules. readFile allocator is caller-supplied; file bytes and staged pixels are borrowed only for the duration stated by each method.
  • Context.factor, renderer, priority, kind (parameters): Zoom factors above 1 zoom in; renderer and preload priority select a supported mode; hot-reload kind identifies how the watched file is interpreted.
  • Context.pixel_height (parameters): Font pixel size must be positive and is fixed into the loaded face or baked resource; bitmap fonts take their size from the descriptor.
  • Context.mouseWorld, capabilities, textureStats, stageFormats (returns): Return value snapshots in world pixels or capability/statistics structs; they do not transfer ownership.
  • Context.pollEvent, takeChanged, takeAssetChanged, fileExistsBeside (returns): Return optional event/change state or file-existence status; polling/consuming change methods remove the returned item from their queue.
  • Context.acquireTexture (returns): Returns one counted TextureHandle reference; release it once with releaseTexture.
  • Context.textureOf (returns): Returns a borrowed pointer to the texture while the handle remains live; do not retain it across release or unload.
  • Context.loadTexture, loadSound, loadAtlas, loadFont, loadMsdfFont, loadOutlineFont, loadBitmapFont (returns): Successful calls return caller-owned resources or a font registry id; deinitialize owned resources and unload font ids with their matching API.
  • Context.openStreamed (returns): Returns a streamed-sound descriptor for playback; no explicit resource deinit is required because each voice opens and closes its reader.
  • Context.registerTexture, requestTexture, retainTexture, releaseTexture, writeFile, removeFile, saveBindings, unloadFont (returns): Successful commands return void; unloadUnusedTextures instead returns the number of GPU textures reclaimed.
  • Context.AssetError and file/audio errors (errors): Missing files, unsafe/overlong paths, decode/format failures, invalid atlas data/dimensions, I/O errors, and allocation failures are returned; callers may retry transient I/O failures or report invalid content.
  • Context.loadFont variants and unloadFont (errors): Font loaders return FontLoadFailed for unsupported or malformed font data, OutOfMemory for allocation failure, and PathTooLong/FileNotFound/ReadFailed for file access; unloadFont reports stale or invalid handles.
  • Context.allocators.asset, allocators.game, allocators.frame, worker_allocator (allocators): Context allocator scopes are borrowed for their documented lifetimes. worker_allocator is thread-safe and used for worker-side decode; caller-owned readFile bytes must be freed by the allocator passed to that call.
  • Context.TextureHandle, FontHandle (handles): TextureHandle is counted and must be released once per acquisition; FontHandle is a non-owning registry id invalidated permanently by unloadFont. Never use either after its release/removal.
  • Context.max_full_path, max_registered_textures (capacities): Relative file paths are bounded by max_full_path bytes; the named texture registry holds at most max_registered_textures entries.
  • Context.uploadStaged (methods): Uploads staged pixels to the GPU on the engine thread. Staged CPU data may be freed as soon as the call returns.

bairava.Event

Kind: type
Stability: experimental
Summary: Platform events translated into the engine’s SDL-independent event model.

  • Event.quit (fields): Window-close request; the event pump handles shutdown and Input.apply does not change state.
  • Event.key_down, key_up (fields): Physical Scancode transitions; key_down.repeat identifies auto-repeat, which input state ignores.
  • Event.mouse_motion (fields): Cursor coordinates x/y in window points.
  • Event.mouse_button_down, mouse_button_up (fields): Transitions for the supported MouseButton enum values.
  • Event.gamepad_added, gamepad_removed (fields): Connection lifecycle for a generation-checked GamepadId; an added id is valid until its matching removal.
  • Event.gamepad_button_down, gamepad_button_up (fields): Button transitions identified by gamepad id and standard GamepadButton.
  • Event.gamepad_axis (fields): Raw axis position identified by gamepad id and GamepadAxis; stick range is -1..1 and trigger range is 0..1, before dead-zone processing.
  • Event.text_input (fields): UTF-8 bytes copied from the active platform text-input session; bounded by TextInput capacity.

bairava.Scancode

Kind: type
Stability: experimental
Summary: Keyboard scancode used by the platform input model.

  • Scancode.all enum values (fields): Physical keyboard positions, independent of the character produced by the active layout. Includes engine command keys and gameplay keys; only the subset represented by Key can be queried as game input.

bairava.GamepadId

Kind: type
Stability: experimental
Summary: Identifier for a connected gamepad.

  • GamepadId.slot (fields): Index in the fixed engine gamepad table, from 0 through max_gamepads - 1.
  • GamepadId.generation (fields): Increases whenever a slot is assigned to another device, preventing a stale id from matching its replacement.
  • GamepadId.GamepadId (handles): A value identifier, not an owning resource handle; the platform creates it and generation checks make stale ids inert.
  • GamepadId.slot (capacities): Valid slot range is 0..max_gamepads - 1; events with an out-of-range slot are ignored.

bairava.TextInput

Kind: type
Stability: experimental
Summary: Text-input event data delivered to game code.

  • TextInput.bytes (fields): Fixed 32-byte storage containing the event’s UTF-8 bytes in the prefix selected by len; bytes after len are not part of the text.
  • TextInput.len (fields): Number of valid UTF-8 bytes, in the range 0..32.
  • TextInput.slice (methods): Returns a borrowed slice of bytes[0..len]; valid only while this TextInput value remains alive.
  • TextInput.slice (returns): Borrowed UTF-8 bytes backed by this value; the returned slice does not own storage.
  • TextInput.bytes (capacities): At most 32 bytes fit in one event; longer native text is truncated to the first 32 bytes, which may split a multibyte code point.

bairava.DrawContext

Kind: type
Stability: experimental
Summary: Frame-scoped rendering context supplied to game draw callbacks.

Contract: Valid only during draw. Submit drawing through its batch; do not retain the context or its frame-owned data.

  • DrawContext.batch (handles): Borrowed frame batch. Queue work only during draw; the engine owns GPU upload and submission.
  • DrawContext.cam (handles): Borrowed camera for this draw. World coordinates must be converted to view pixels before APIs that accept view-space coordinates.
  • DrawContext.view_w, view_h (fields): Current view dimensions in pixels; coordinate-space inputs to drawing are in this view.
  • DrawContext.alpha (fields): Interpolation factor from previous update (0) to latest update (1), intended for render-only interpolation.
  • DrawContext.dt (fields): Elapsed seconds since the previous presented frame, capped by the frame loop; use for frame-rate-independent presentation smoothing.
  • DrawContext.debug (handles): Borrowed debug-shape queue valid only for this draw; submit view-pixel shapes only when the corresponding show switch is enabled.
  • DrawContext.show (fields): Debug geometry visibility switches controlled by development commands and F4.
  • DrawContext.layers (fields): Game-owned tile-layer visibility flags that development commands may change.

bairava.Allocators

Kind: type
Stability: experimental
Summary: Allocator set available to game code through the engine context.

  • Allocators.game (fields): Persistent game-instance allocator; game-owned allocations must be released or allowed to expire with that instance.
  • Allocators.asset (fields): Allocator for loaded asset data whose lifetime is the current run.
  • Allocators.frame (fields): Temporary allocator whose allocations are valid only until the next outer frame begins.
  • Allocators.game, asset, frame (allocators): Borrowed allocator interfaces owned by the active engine run; do not retain them beyond their documented scope or deinitialize them.

bairava.run

Kind: function
Stability: experimental
Summary: Runs a game through initialization, fixed-step updates, drawing, and shutdown.

Contract: The game type supplies init, update, and draw, plus optional teardown. init errors are returned and do not call game teardown; resources created before an init error must be released by init. A successful init is paired with teardown before platform resources are destroyed. update uses a fixed timestep; draw runs once per presented frame.

  • run.Game.init (callbacks): Called once on the engine thread after platform/runtime setup. An init error is returned by run and does not call game teardown; init must release any resources it acquired before failing.
  • run.Game.update (callbacks): Called zero or more times per rendered frame at the fixed update_hz rate. The Context and its input/dt are borrowed for that call.
  • run.Game.draw (callbacks): Called on the engine thread for each presented frame, after updates. DrawContext and frame-owned references must not escape the callback.
  • run.Game.deinit (callbacks): Optional teardown called exactly once after successful init, before platform and GPU resources are destroyed.
  • run.Config.allocator (allocators): The allocator supplied in Config must outlive the complete run call.

bairava.Effect

Kind: type
Stability: experimental
Summary: Post-processing effect that can be enabled in application configuration.

bairava.PostParams

Kind: type
Stability: experimental
Summary: Strength parameters consumed by the post-processing effects.

  • PostParams.vignette (fields): Expected strength from 0 to 1; zero disables corner darkening.
  • PostParams.scanline_dim (fields): Expected strength from 0 to 1 controlling brightness of dimmed scanline rows.
  • PostParams.grayscale (fields): Expected strength from 0 to 1; zero preserves color and one produces full grayscale.
  • PostParams.padding (fields): Reserved layout padding; not used as an effect strength and normally left at zero.

bairava.Input

Kind: type
Stability: experimental
Summary: Current keyboard, mouse, and gamepad input state.

Contract: Query during update. Press/release edges are latched for exactly one fixed update, while held state and mouse coordinates reflect the latest event pump.

  • Input.held_keys, pressed, released, pending_pressed, pending_released (fields): Key state and event-edge arrays indexed by Key enum value. Prefer held/wasPressed/wasReleased; direct mutation can desynchronize pending events.
  • Input.mouse_held, mouse_pressed, mouse_released, pending_mouse_pressed, pending_mouse_released (fields): Mouse button state and event-edge arrays indexed by MouseButton; held state is live, while edges are latched for one update. Prefer the mouse query methods.
  • Input.mouse_x, mouse_y (fields): Current cursor position in window points, not view/world pixels. Use Context.mouseWorld for world coordinates.
  • Input.pads, connections (fields): Gamepad slots and connection ordering used to select the primary device; treat as input implementation state and query through primaryPad.
  • Input.latch (methods): Transfers queued input edges into the current update snapshot and clears pending edges; the runtime calls it once before each update.
  • Input.held, wasPressed, wasReleased (methods): Query key state: held is live to the latest event pump; press/release are true only in the update step receiving that edge.
  • Input.mouseDown, mousePressed, mouseReleased (methods): Query mouse-button held state and one-update press/release edges.
  • Input.primaryPad (methods): Returns a borrowed pointer to the earliest-connected still-present gamepad slot, or null if none is connected. A later controller does not become primary until the earlier one disconnects.
  • Input.snapshot, restoreSnapshot (methods): Copy or restore deterministic update-visible input state; restoring clears platform events pending for a later step.
  • Input.heldCount, pressedCount, heldMask, addHeldNames (methods): Diagnostics helpers that count held/pressed keys, pack held keys by enum ordinal, or append held key names to a caller-provided list.
  • Input.setHeld, sampleHeld (methods): Platform sampling helpers. sampleHeld queries every supported key once; game code normally reads state rather than setting it.
  • Input.apply (methods): Consumes one platform-neutral Event; key auto-repeat and quit do not create input state changes.
  • Input.keyDown, keyUp, moveMouse, mouseButton, gamepadAdded, gamepadRemoved, gamepadButton, gamepadAxis (methods): Record translated platform events into held state and pending edges. The runtime/platform normally calls these; applying an unknown or stale gamepad ID has no effect.
  • Input.primaryPad (returns): The pointer is borrowed from Input and is invalidated by mutation/replacement of its pad slot; do not retain across input updates.
  • Input.snapshot (returns): Returns a by-value copy of update-visible input, suitable for deterministic save/restore; pending platform edges are not included.
  • Input.held, wasPressed, wasReleased, mouseDown, mousePressed, mouseReleased (returns): Return true only when the corresponding key/button condition is met; edge results are scoped to one latched update.
  • Input.heldCount, pressedCount, heldMask (returns): Return key counts or a u64 key-ordinal bit mask; the mask has one bit for each supported Key.
  • Input.sampleHeld.isHeld (callbacks): Called synchronously once per Key while sampleHeld runs; it must return whether that key’s Scancode is down and must not retain engine-owned state.
  • Input.primaryPad (handles): The returned slot pointer is borrowed from the Input value; it is not owned and must not be freed. Re-query after input mutation.
  • Input.sampleHeld.isHeld (parameters): A compile-time function taking Scancode and returning bool; it supplies physical held state for each supported Key.
  • Input.moveMouse.x, moveMouse.y (parameters): Cursor coordinates in window points, as delivered by the platform; they are not converted to view or world coordinates.
  • Input.gamepadAxis.value (parameters): Normalized platform axis value; stick axes are signed and trigger axes are non-negative.
  • Input.pads (capacities): Tracks up to max_gamepads (8) devices; added devices beyond the available slots are ignored.

bairava.Key

Kind: type
Stability: experimental
Summary: Keyboard key values used by input bindings.

  • Key.all enum values (fields): Supported keyboard key identities (escape, arrows, WASD, and the listed control keys). They represent physical scancodes, not layout-dependent characters; F3 and F11 are engine commands rather than Key values.

bairava.Binding

Kind: type
Stability: experimental
Summary: Physical control that can be assigned to a game action.

  • Binding.key, mouse, gamepad_button (fields): Bind one keyboard Key, MouseButton, or standard GamepadButton. Gamepad bindings read the primary connected pad.
  • Binding.gamepad_axis (fields): Binds one axis and direction half. Stick directions have negative and positive halves; triggers only have a positive half.
  • Binding.gamepad_axis.axis, direction (parameters): Axis selects the stick/trigger; direction selects which half is active. Axis strength is normalized past a dead zone.

bairava.ActionMap

Kind: type factory
Stability: experimental
Summary: Maps game-defined actions to configurable physical input bindings.

  • ActionMap.Action (parameters): The compile-time type argument must be an enum owned by the game; each enum tag has an independent binding list.
  • ActionMap.fromDefaults (methods): Copies each action’s default binding slice into fixed per-action storage. More than max_bindings_per_action defaults is a programmer error and panics.
  • ActionMap.set (methods): Replaces one action’s bindings by copying the supplied slice; caller must keep its length at or below max_bindings_per_action.
  • ActionMap.bindingsOf (methods): Returns a borrowed slice in binding order; valid while the map storage remains alive and unchanged.
  • ActionMap.held, pressed, released, value (methods): Evaluate the bound action against one Input state. Any held binding makes held true; value is the strongest binding from 0 to 1; edges last one update.
  • ActionMap.addHeldNames (methods): Append the enum names of all currently held actions to a caller-provided list, in action enum order.
  • ActionMap.bindings, counts (fields): Fixed-capacity copied binding storage and per-action lengths. Prefer the public methods instead of mutating these arrays directly.
  • ActionMap.fromDefaults, set (capacities): Each action accepts at most max_bindings_per_action (4) bindings. fromDefaults panics if exceeded; set requires the caller to uphold the limit.
  • ActionMap.bindingsOf (returns): Returns a borrowed slice into this map; do not retain it after map deinitialization or concurrent mutation.
  • ActionMap.fromDefaults (errors): Panics when any default binding slice exceeds max_bindings_per_action; validate caller-supplied defaults before construction.
  • ActionMap.set.list, held/pressed/released/value.state (parameters): The binding list must fit the fixed per-action capacity. Query state is borrowed for the call and should be the Input snapshot for the current update.
  • ActionMap.held, pressed, released, value (returns): Return action state as bool or an analog strength in the inclusive range 0..1; a missing primary gamepad makes gamepad bindings inactive.

bairava.ActionBuffer

Kind: type factory
Stability: experimental
Summary: Simulation-owned press windows for selected input actions.

  • ActionBuffer.Action (parameters): The compile-time type argument must be the same game-owned action enum used by ActionMap.
  • ActionBuffer.setWindow (methods): Sets the action’s buffer duration in seconds; negative and non-finite values disable buffering.
  • ActionBuffer.begin (methods): Advance once per fixed update after input is latched. dt is fixed-step seconds; new presses arm/refresh the window and other active windows age by one update.
  • ActionBuffer.pending, consume (methods): pending observes an unexpired press; consume returns and clears it so one buffered press cannot trigger twice.
  • ActionBuffer.windows, remaining (fields): Per-action durations and remaining fixed-update ticks. Treat these as implementation state; use setWindow and query methods.
  • ActionBuffer.begin.dt (parameters): The fixed simulation step in seconds. Invalid or non-positive dt produces no buffered ticks.
  • ActionBuffer.consume (returns): Returns whether the selected action had an unexpired press, then clears it; false means there is no pending press.

bairava.ActionDefaults

Kind: type factory
Stability: experimental
Summary: Default binding table for a game’s action enum.

  • ActionDefaults.Action (parameters): The compile-time type argument must be the game-owned action enum used to create its ActionMap.
  • ActionDefaults.each action entry (fields): An enum-indexed slice of default Binding values. The slices are borrowed when passed to ActionMap.fromDefaults, which copies their contents.
  • ActionDefaults.init (methods): Constructs the enum-indexed table from a struct literal whose fields match the Action enum tags.

bairava.Camera

Kind: type
Stability: experimental
Summary: 2D camera state and world-to-screen coordinate conversion.

Contract: Keep the camera in world-pixel coordinates. Follow methods clamp the view to the world; view dimensions must be positive and world/view dimensions should be updated consistently when zoom or the viewport changes.

  • Camera.x, y (fields): Unrounded world-pixel coordinates of the visible view’s top-left. Conversion methods round sprite positions once after subtracting these values.
  • Camera.view_w, view_h (fields): Visible view dimensions in world pixels, after zoom; must be positive for follow operations.
  • Camera.world_w, world_h (fields): World bounds in pixels used to clamp the camera so the view stays inside the world.
  • Camera.placed (fields): False before the first successful follow; the first placement snaps instead of easing or applying a prior dead-zone.
  • Camera.zoom (fields): Positive multiplicative zoom; 1 is normal, above 1 shows less world, and below 1 shows more. The engine derives visible view dimensions from it.
  • Camera.viewRect (methods): Returns the current world-space visible rectangle without modifying camera state.
  • Camera.follow, followWith (methods): Centers on a world-pixel target and clamps to world bounds; followWith also applies dead-zone, look-ahead, and keep-inside constraints.
  • Camera.followSmooth, followSmoothWith (methods): Eases toward the constrained target using a frame-rate-independent exponential rate. The first call snaps; rate <= 0 snaps thereafter.
  • Camera.approachZoom (methods): Eases toward a positive zoom target geometrically; invalid target falls back to 1, and non-positive rate snaps.
  • Camera.zoomTarget (methods): Multiplies current zoom by factor and clamps the result to caller-provided lo..hi bounds; caller must supply valid positive bounds.
  • Camera.screenX, screenY (methods): Convert one world coordinate to whole view pixels by subtracting the camera origin and rounding once.
  • Camera.offset, scrolled (methods): Return draw-only camera copies; offset adds a finite pixel displacement, while scrolled applies independent parallax factors and pixel offsets. The original camera is unchanged.
  • Camera.Constraint.lead_x, lead_y (fields): World-pixel look-ahead applied after dead-zone tracking and capped to half the view.
  • Camera.Constraint.dead_x, dead_y (fields): Dead-zone half-extents as fractions of view size, clamped to 0..0.5.
  • Camera.Constraint.limit_x, limit_y (fields): Hard keep-inside half-extents as fractions of view size, clamped to 0..0.5.
  • Camera.Scroll.factor_x, factor_y (fields): Independent parallax factors applied to camera origin; 1 follows the camera fully and 0 keeps the layer fixed.
  • Camera.Scroll.offset_x, offset_y (fields): World-pixel offsets added after each parallax factor.
  • Camera.followWith.constraint, followSmoothWith.constraint (parameters): Constraint values use world pixels for lead and fractions of visible view size for dead-zone and hard-limit extents.
  • Camera.followSmooth.dt, rate (parameters): dt is elapsed seconds and should be nonnegative; rate is exponential response per second. A zero or negative rate snaps.
  • Camera.approachZoom.target, dt, rate (parameters): Target zoom must be positive; dt and rate are seconds and response-per-second respectively. A zero or negative rate snaps.
  • Camera.zoomTarget.current, factor, lo, hi (parameters): factor above 1 zooms in and below 1 zooms out; lo and hi are the inclusive zoom bounds and must be ordered and positive.
  • Camera.offset.dx, dy (parameters): Draw-space camera displacement in world pixels; non-finite offsets are ignored.
  • Camera.scrolled.scroll (parameters): Parallax factors and offsets are independently applied to the camera’s x and y origins.
  • Camera.viewRect, offset, scrolled (returns): Return a value copy; no camera-owned resource or borrowed reference is returned.
  • Camera.screenX, screenY (returns): Return a rounded view-pixel coordinate; no world-to-window scaling is applied here.

bairava.Shake

Kind: type
Stability: experimental
Summary: Deterministic game-owned draw-time camera shake.

  • Shake.trauma (fields): Shake severity in 0..1; add clamps valid additions to this range, and sample uses its square as amplitude.
  • Shake.max_offset (fields): Maximum displacement amplitude in view pixels at full trauma.
  • Shake.frequency (fields): Noise phase units advanced per second by update.
  • Shake.decay (fields): Trauma removed per second by update; set to zero to prevent decay.
  • Shake.seed (fields): Deterministic noise seed; equal seeds and phase sequences produce equal samples.
  • Shake.phase (fields): Noise phase accumulated during update; game-owned if it needs synchronized/reproducible shake.
  • Shake.add (methods): Adds nonnegative finite trauma, clamped at 1; negative or non-finite amounts are ignored.
  • Shake.update (methods): Advance once per draw with elapsed seconds; invalid or negative dt leaves state unchanged.
  • Shake.sample (methods): Produces deterministic, smoothly interpolated x/y offsets scaled by squared trauma; call without mutating state.
  • Shake.add.amount (parameters): Nonnegative finite trauma increment; values above 1 saturate final trauma at 1.
  • Shake.update.dt (parameters): Elapsed draw-frame seconds; finite nonnegative values advance phase and decay.
  • Shake.sample (returns): Returns a two-component displacement in view pixels; zero trauma or invalid amplitude returns {0, 0}.

bairava.SpriteBatch

Kind: type
Stability: experimental
Summary: Frame-local sprite and lighting submissions for the renderer.

Contract: Use only from the draw callback. Submission order and z values control layering; the renderer owns upload and flush. The batch is not an independently initialized or drawable backend object.

  • SpriteBatch.allocator (allocators): Allocator supplied by the engine for dynamically growing per-frame quad, vertex, and batch arrays; the batch owns those allocations.
  • SpriteBatch.quads, sprite_count (fields): Queued sprite records and the number currently used; drawSprite appends and begin resets the count.
  • SpriteBatch.vertices, vertex_count, batches, batch_count (fields): Prepared CPU vertex and texture-run arrays, rebuilt by prepare from queued sprites. Their pointers may move when capacity grows.
  • SpriteBatch.draw_calls (fields): Number of texture runs actually submitted by the most recent renderer draw.
  • SpriteBatch.projection (fields): Pixel-to-clip transform set by begin for the current viewport.
  • SpriteBatch.lighting, light_count, shadow_segment_count, has_lit_runs (fields): Per-frame light uniforms and counts, reset by begin; has_lit_runs is set during prepare when a sprite uses a normal map.
  • SpriteBatch.allocator, gpu_state, flat_normal, white (handles): Batch-owned allocator/backend state and helper textures; do not retain, replace, or release these pointers independently.
  • SpriteBatch.begin (methods): Starts the frame and clears queued sprites, lights, shadows, and counters. The runtime calls it before game draw.
  • SpriteBatch.setAmbient (methods): Sets RGB ambient brightness for lit sprites; begin restores full ambient light each frame.
  • SpriteBatch.addLight (methods): Adds one view-space point light; returns false without modifying the batch when max_lights is reached.
  • SpriteBatch.addShadowSegment (methods): Adds one view-space occluder; returns false without modifying the batch when max_shadow_segments is reached.
  • SpriteBatch.addPointLightComponents, addShadowSegmentComponents (methods): Adds enabled values in input order and stops at capacity; the returned count is the number accepted.
  • SpriteBatch.addPointLightWorld, addShadowSegmentWorld (methods): Collects enabled components from ECS rows in iteration order, supporting AoS or SoA row storage, and stops when the relevant per-frame capacity is full.
  • SpriteBatch.drawSprite (methods): Queues one sprite using texel-space src and pixel-space dst; prepare sorts by z, depth_y, and insertion order, then renderer submission samples the referenced texture.
  • SpriteBatch.prepare (methods): Sorts queued sprites and builds vertices and adjacent texture runs; may be called repeatedly and rebuilds the same frame result.
  • SpriteBatch.deinit (methods): Releases backend and batch-owned GPU/CPU resources. The engine normally owns this lifecycle; game code should not deinitialize DrawContext.batch.
  • SpriteBatch.max_lights, max_shadow_segments (capacities): Fixed per-frame light and shadow capacities. Add methods report overflow through false or a partial accepted count.
  • SpriteBatch.quads, vertices, batches (capacities): Sprite, vertex, and texture-run storage grows as needed; there is no per-frame sprite or texture-switch limit, but storage growth uses the batch allocator.
  • SpriteBatch.begin.viewport_w, viewport_h (parameters): Viewport width and height in pixels with origin at the top-left; used to build the pixel projection.
  • SpriteBatch.setAmbient.rgb (parameters): Ambient RGB brightness, conventionally channel values from 0 to 1.
  • SpriteBatch.addLight.light, addShadowSegment.segment (parameters): Light and segment positions/radii are expressed in view pixels, not world coordinates.
  • SpriteBatch.component and world collection methods (parameters): Slices are borrowed during the call. ECS world rows must expose count(), rows.get(index), and the requested component field or component type.
  • SpriteBatch.drawSprite.texture_ref (parameters): Borrowed texture pointer retained by the queued sprite; the texture must remain alive through renderer submission.
  • SpriteBatch.drawSprite.src, dst, opts (parameters): src is a texel rectangle, dst is a viewport-pixel rectangle, and Options controls tint, alpha, flips, pivot, rotation, and sort order.
  • SpriteBatch.addLight, addShadowSegment (returns): Return true if accepted; false means the corresponding fixed per-frame capacity is full and the batch is unchanged.
  • SpriteBatch.component and world collection methods (returns): Return the number accepted before capacity was reached; disabled components do not count.
  • SpriteBatch.drawSprite (errors): Panics for non-finite depth_y, a normal map whose dimensions differ from its sprite texture, or a request to light a coverage/MSDF font texture.
  • SpriteBatch.deinit (errors): Must be called at most once and only while the owning renderer/device is alive; it invalidates the batch value.

bairava.SceneHost

Kind: type factory
Stability: experimental
Summary: Generic scene-host type specialized for a game root type.

Contract: Instantiate with the root scene type and pass the resulting type to bairava.run. Scene callbacks are driven by the host; transitions are applied after update at a safe point.

  • SceneHost.Root.init (callbacks): Constructs a scene from a borrowed Context. The host owns the returned scene value; an init error leaves the existing scene stack active.
  • SceneHost.Root.update (callbacks): Runs only for the active scene; receives a borrowed Context and SceneNavigator. Requests are deferred until the update safe point.
  • SceneHost.Root.draw (callbacks): Draws open scenes bottom-to-top; DrawContext is borrowed for the callback.
  • SceneHost.Root.deinit / Root.deinitWithContext (callbacks): Optional teardown runs once when a scene is popped, replaced, or the host shuts down. Use deinitWithContext when resource release needs Context.
  • SceneHost.Ctx.allocators.game (allocators): The host uses the run’s game allocator for scene stack and scene-owned storage; that allocator must outlive the host and is supplied by Context.
  • SceneHost.Root.init (errors): The root scene’s initialization error is returned from host init. Later transition initialization errors are logged, and the currently open stack remains active.
  • SceneHost.push, pop (errors): A push past max_depth or pop of the root is rejected at the transition safe point; SceneHost logs the error and continues with the existing scene stack.
  • SceneHost.max_depth (capacities): The host stack holds at most eight open scenes; extra push requests are refused without changing the stack.

bairava.SceneNavigator

Kind: type
Stability: experimental
Summary: Navigation handle for requesting scene transitions.

Contract: Borrowed for the active scene’s update callback. A request is recorded and applied after updates at the next safe point; a later request replaces an earlier pending request.

  • SceneNavigator.switchTo (methods): Requests replacement of the active scene while keeping scenes below it open. The new scene is initialized before the replaced scene is released.
  • SceneNavigator.push (methods): Requests a new scene above the active scene, suspending but continuing to draw the prior scene. Applying beyond max_depth fails and leaves the stack unchanged.
  • SceneNavigator.pop (methods): Requests closing the active scene so the one below resumes. Popping the root is rejected when the request is applied; use switchTo to replace it.
  • SceneNavigator.pending (fields): Internal deferred transition request; the host applies it after update. Do not read or mutate this field directly.
  • SceneNavigator.max_depth (capacities): The scene stack holds at most eight scenes; an over-capacity push is refused when pending transitions are applied.
  • SceneNavigator.SceneNavigator (handles): Borrowed during the active scene’s update callback; do not retain it after update returns.
  • SceneNavigator.switchTo.T, push.T (parameters): Compile-time scene type implementing the host’s lifecycle callbacks; the requested scene is constructed and transitioned at the next safe point.
  • SceneNavigator.push, pop, scene init (errors): Requests return no error immediately. At application, a full stack, root pop, or requested scene init failure is reported by the host logger; the previous stack remains active.
